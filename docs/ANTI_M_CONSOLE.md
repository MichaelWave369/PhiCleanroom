# PR #11: Public Anti-M completion console

The PhiCleanroom React GitHub Pages site now has a read-only Anti-M
section. It reconciles four **locally selected files** from the separate
Python Anti-M v1 workflow:

1. completion-contract.json generated by Anti-M contract
2. Builder receipt JSON generated by the reference worker
3. Independent verification receipt JSON from the verifier
4. Exact quarantined search.py source code (hashed, never executed)

Use the Anti-M link in the website navigation. The files are processed in
your browser tab using native File APIs and Web Crypto SHA-256. No files
are uploaded, no model APIs are used, and no private Vault connection is
established.

## How to use

1. Finish the authorized local Vault review, restricted reference builder,
   independent verifier and Anti-M contract per VAULT.md, BUILDER.md,
   VERIFICATION.md, and ANTI_M.md.
2. Pick your completion contract, original builder receipt, original
   verifier receipt and corresponding search.py using the four inputs.
3. Check the local SHA-256 and lineage rows. They compare actual selected
   receipt/source *file bytes* against hashes in the frozen contract,
   plus the stage, spec, source, builder image and verifier image bindings.
4. Check the displayed seven acceptance-test results and three
   source-derived mutation results, which are declarations from the
   loaded verifier receipt, not independently replayed in the browser.
5. Use the local Python Anti-M CLI to recheck the **current** private
   Vault ledger and review state before deciding on a release.

The Load Synthetic Demo button fabricates a consistent contract,
both receipts and a source digest entirely in the browser. This is
only a teaching example. It does not execute a test suite, run Docker,
check human identity or issue a real completion record.

## Status definitions

- LOCAL FILE LINKS MATCH: all four input files are present, their
  structures and digest references agree, and the linked schemas
  contain required fields. This is NOT release approval or DONE.
- AWAITING COMPLETE EVIDENCE: one or more selected files are missing.
- LOCAL EVIDENCE MISMATCH: a selected byte digest or identifier conflicts
  with the contract.
- Live Vault ledger and reviewer identity: **NOT CHECKED**, always,
  including when the synthetic demo displays all local matches.

A malicious user can fabricate an internally consistent set of receipts.
Local hash agreement therefore does **not** establish evidence authenticity,
reviewer identity, that a Docker test ran, that a mutation was actually
produced, a stable externally anchored ledger or security of generated code.

## Critical trust and privacy limitations

- Never load an attestation secret or HMAC key into this public console.
  It has no signing, approval, release or DONE buttons.
- The actual Anti-M completion and keyed attestation routines exist
  only in the private Python CLI. Signing keys prove local key possession,
  not public human identity authentication.
- The site never imports or executes the selected source file; it only
  computes its byte digest.
- JSON inputs are bounded to 32 KiB each, source to 16 KiB, and duplicate
  JSON object field names are rejected.
- Only parsed JSON metadata and hashes remain in React state after
  hashing; they are cleared on reset or reload. The browser may
  internally retain data until process memory is reclaimed.
- This is remotely delivered JavaScript and may load public Google Fonts.
  Sensitive or protected investigator material should be checked with
  the local Python CLI rather than through any hosted application.
- The browser cannot revalidate the real private Vault, confirm a
  human-held HMAC key or prove a sign-off was genuinely human.
- The reference workflow still supports just one synthetic exact-title
  search example, not arbitrary software contracts.

## Tests and deployment

From the web directory run:

    npm install
    npm test
    npm run build

The negative tests cover changed source/receipt digests, invalid
lineage, omitted mutants, fake approval states, forged Docker policy,
malformed/duplicate JSON, oversize inputs, no Web Crypto and full React
server rendering.

A GitHub Actions workflow runs the site tests and Vite build in PRs and
publishes from main after merge. This feature never deploys any generated
builder source or runs Anti-M against a private remote Vault.
